## Воспроизводимая сборка и автотесты

Из каталога плагина в PowerShell:

```powershell
.\Tools\Test-Plugin.ps1 -EngineRoot 'E:\UE_5.8'
```

Дополнительно проверить Shipping:

```powershell
.\Tools\Test-Plugin.ps1 -EngineRoot 'E:\UE_5.8' -BuildShipping
```

Скрипт создаёт новый временный host-project, копирует только Source и descriptor плагина, собирает DLL отдельно от открытого игрового проекта и запускает `WorldMap.*` через UE Automation. Существующие выходные каталоги отклоняются; скрипт ничего рекурсивно не удаляет. Точный путь к логам и JSON-отчёту выводится в консоль. UnrealBuildTool также может писать обычные кэши/логи в пользовательские каталоги Unreal.

Можно указать собственный **новый** каталог через `-OutputDirectory`. Не коммитьте сгенерированные DLL, Intermediate, Saved, логи и test reports.

В редакторе эти же тесты находятся в `Tools → Test Automation` / Session Frontend → Automation по фильтру `WorldMap` (расположение окна зависит от раскладки редактора).

## Что проверяют тесты

| Тест | Сценарий |
|---|---|
| `Geometry.ProjectionRoundTrip` | Обратимость world/widget-проекции при разных масштабах, поворотах, крупных координатах; привязка zoom к курсору |
| `Geometry.ConcaveAndInvalidPolygons` | Вогнутый контур, обратный порядок вершин, площадь треугольников, запрет самопересечений |
| `Registration.InstancesStreamingAndDeltaBudget` | Разные namespace экземпляров, снимок после выгрузки источника, постепенная публикация, массовый отзыв |
| `Floors.AuthoritativeVolumesAndHysteresis` | Серверное попадание в объём, исследование, задержка перехода, сохранение этажа вне областей |
| `Security.AudienceAndTeamExploration` | Публичная карта, отдельные команды, role bypass, позднее назначение игрока, смена команды, owner-only relevancy |
| `Security.ClientCannotMutateAuthority` | Simulated proxy не меняет регистрацию, состояние, исследование, роль или наблюдения; функции назначения не RPC |
| `Security.ObservationSamplesAndIndependentSources` | Нет несообщённого движения/этажа, данные не попадают чужой команде, память и независимые источники |
| `Security.StateAccessDoesNotExposePrivateMetadata` | Состояние скрывается отдельно от геометрии |
| `Security.PingValidation` | Скрытая область, частота, дальность/геометрия, квота, audience, срок жизни, DA whitelist |

Тестовый мир использует настоящие классы Unreal и серверные пути плагина. Это функциональные проверки логики в одном процессе, **не тест передачи пакетов между отдельными клиентами**.

## Обязательная сетевая матрица проекта

Перед релизом игры прогоните хотя бы:

1. Dedicated server + два клиента отдельными процессами; затем listen server + клиент.
2. Две разные команды и одинаковая команда; обычная роль и обход исследования.
3. Подключение после исследования и существующего пинга; отключение автора пинга.
4. Смена команды/роли, массовый отзыв большого числа элементов.
5. Пакетные задержки/потери: наблюдение истекает, пинги не превращаются в гарантированную очередь спама.
6. Цель выходит из Actor relevancy или выгружается: клиент не получает новые координаты через другие системы игры.
7. Несколько локальных игроков, если проект поддерживает split-screen; правильный Owning Player каждого виджета.
8. Имеющийся в проекте Replication Graph/Iris и BP-наследники viewer сохраняют owner-only delivery.
9. Стриминг Level Instance, одинаковые шаблоны с разными namespace, восстановление сохранений.

Для UI проверьте DPI, размеры viewport, круговую маску проекта (если используется), hover на перекрывающихся объектах, смену этажа и zoom под курсором. Для города измерьте время сервера, Slate и объём репликации на реальном количестве элементов.

## Проверка стартовых ассетов

`Tools/CreateStarterAssets.py` можно выполнить в отдельном тестовом проекте с Python Editor Script Plugin. Он создаёт DA и компилирует BP-наследников. Повторный запуск должен сообщить о нуле новых ассетов и сохранить пользовательские изменения.

В этой версии в Git хранятся исходники и скрипт, а не бинарные uasset-примеры. Поэтому стартовые ассеты создаются редактором текущей версии UE и принадлежат проекту пользователя.
