# Документация WorldMapSystem

[Обзор плагина](../README.md)

Система строит для каждого игрока разрешенное представление карты: геометрию, исследованные области, наблюдения и пинги. В UI попадает выборка персонального viewer, а не полный серверный реестр.

## Если Ты Впервые Работаешь С Системой

1. [Первый запуск](FirstRun.md): создайте настройки, менеджер, две области и назначьте viewer.
2. [Архитектура](DeveloperGuide.md): разберитесь с DA, идентификаторами, областями и наблюдениями.
3. [Сеть и безопасность](Security.md): проверьте команды, роли и приватность.
4. [Атлас Blueprint-нод](BlueprintAtlas.md): подключите миникарту, большую карту и пинги.
5. [Примеры](Examples.md), затем [проверки](Testing.md): проверьте свой сценарий на двух клиентах.

## Термины, Которые Нужно Запомнить

- `Manager` хранит полный серверный реестр и знания команд.
- `Viewer` принадлежит PlayerController и получает только разрешенные этому игроку данные.
- `Element Definition` описывает тип элемента, форму, стиль и правила видимости.
- `Element Id` отличает конкретные экземпляры одного типа.
- `Exploration Id` объединяет элементы одной исследуемой области.
- `Instance Namespace` отличает повторные экземпляры процедурной комнаты.
- `Observation` хранит серверный снимок обнаруженного объекта и срок актуальности/памяти.

## Главное Правило UI

Создайте виджет с правильным `Owning Player`; он ищет его viewer, в том числе после позднего получения по сети. Миникарта и большая карта имеют независимые масштаб и выбранный этаж. После смены команды прежний viewer заменяется: не сохраняйте его записи как актуальные.

## Главное Правило Gameplay

Команды, роли и обнаружения назначает сервер. Карта не проверяет зрение сама. Локальная метка и нажатие на tooltip не подтверждают обнаружение и не разрешают игровое действие.

## Как Читать Примеры

Названия классов, свойств и нод оставлены как в API, чтобы их можно было найти в Editor. `DA` означает Data Asset, `BP` - Blueprint, `PIE` - запуск в редакторе, `snapshot` - снимок текущего состояния. Примерное имя `DA_*` не означает наличие готового ассета в поставке: создай его по инструкции, если явно не указан другой способ.

Читай первый запуск по порядку, проверяй ожидаемый результат каждого сценария, затем используй атлас как справочник. Разделы проверок отделяют план приемки от фактически выполненных тестов. Сохраненные исторические имена файлов нужны для совместимости ссылок; актуальный маршрут чтения собран в этом индексе.
